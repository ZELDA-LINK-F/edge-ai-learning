## 二、坑 1：摄像头完全不认（最隐蔽的一个）

### 症状
```
· /dev/video* 不存在
· 内核日志里连 imx219 探测记录都没有
· i2c-10 / i2c-11 总线消失（对比 10-15 号是有的）
· 硬件明明接着，却像"根本没这回事"
```

### 排查过程
| 步骤 | 检查 | 发现 |
|---|---|---|
| 1 | `ls /dev/video*` | 不存在 |
| 2 | `journalctl -k \| grep imx219` | **连探测都没有**（不是失败，是没试） |
| 3 | `ls /dev/i2c-*` | i2c-10/11 消失 |
| 4 | `cat /proc/device-tree/model` | **变成 "Orin Nano..."**（10-15 时是 "Orin NX..."）→ 设备树被换过 |
| 5 | `strings` DTB 找 imx219 | 旧新 DTB 里都没有 |
| 6 | `find / -name "*.dtbo"` | **找到 `/boot/tegra234-p3767-camera-p3768-imx219-A.dtbo`** |
| 7 | 看 `/boot/extlinux/` | **发现三个配置文件**（当前 + 两个备份） |
| 8 | 对比备份 | **找到根因** |

### 根因
```
更新前的备份（extlinux.conf.nv-update-extlinux-backup）：
    DEFAULT JetsonIO        ← 启动带摄像头 overlay 的配置

更新后（当前 extlinux.conf）：
    DEFAULT primary         ← 启动不带摄像头的配置

而带摄像头的配置一直都在文件里：
    LABEL JetsonIO
        MENU LABEL Custom Header Config: <CSI Camera IMX219 Dual>
        FDT /boot/dtb/kernel_tegra234-p3768-0000+p3767-0000-nv-super.dtb
        OVERLAYS /boot/tegra234-p3767-camera-p3768-imx219-dual.dtbo
```

**一次系统更新（L4T 36.4.4 → 36.4.7，894 个包）把 `DEFAULT` 从 `JetsonIO` 改回了 `primary`，摄像头配置整个失效。**

### 修复
```
sed -i 's/^DEFAULT primary$/DEFAULT JetsonIO/' /boot/extlinux/extlinux.conf
（先备份到 extlinux.conf.bak-manual）
重启生效
```

### ⚠️ 交叉验证：厂家教程证实了这个配置
桌面上的《Jetson orin super6.2系统配置摄像头使用教程.pdf》原文：
> 「硬件连接到 CAM0 这个 22pin 接口上的摄像头，但是选择 "Camera IMX219-cam0" 是不行的。
>   要选 "Camera IMX219 Dual" 或者 "Camera IMX219-cam1"」

**我们用的正是 `imx219-dual`** —— 和厂家要求一字不差。

### 教训
> **系统更新可能改写 `/boot/extlinux/extlinux.conf` 的 DEFAULT 标签，导致设备树 overlay 静默失效。**
> **排查方法**：对比 `/boot/extlinux/*.nv-update-extlinux-backup` 与当前文件。
> **预防**：更新前备份 extlinux.conf 并记录 DEFAULT 值。

## 三、坑 2：CUDA 大块内存分配失败（ASR 跑不起来）

### 症状
```
funasr 加载 SenseVoiceSmall 时：
    RuntimeError: NVML_SUCCESS == r INTERNAL ASSERT FAILED
                  at CUDACachingAllocator.cpp:838
伴随内核报错：
    NvMapMemAllocInternalTagged: error 12   ← ENOMEM
```

### 排查（每一步都排除了一种可能）
| 假设 | 验证 | 结论 |
|---|---|---|
| 内存不足 | `free` 显示可用 4.8G | ❌ 排除 |
| 内存碎片 | 重启后仍失败 | ❌ 排除 |
| CMA 池被桌面占 | CmaFree 222MB 仍失败 | ❌ 排除 |
| 驱动被更新 | 对比确实升到 36.4.7 | ⚠️ 相关但非全部 |
| funasr 特定路径 | 导入 funasr 后分配 1200MB 正常 | ✅ **问题在 AutoModel 加载路径** |

### 关键实验数据
```
· 模型只有 234M 参数 = 0.94 GB（FP32）—— 不是"模型太大"
· 全新进程里连续分配 2GB、持有 3GB 都正常
· 但在 funasr 进程里，800MB 单块分配失败
· 逐个参数搬移（917 个小块）曾经成功过一次
→ 典型的"大块连续分配失败，小块正常"
```

### 绕过方案（采用的）
**让 ASR 跑在 CPU 上。**
```
device="cpu"  →  加载 3.6 秒 + 识别 3.4 秒
与 GPU 模式相比：慢约 3 秒，但省下 1~3GB 显存
```

**对语音助手场景完全够用**，而且符合 8GB 设备"资源要取舍"的原则。

### 待解决（记录在案）
- GPU 路径失败的确切原因未完全定论（怀疑与 36.4.7 驱动的 NvMap 分配路径有关）
- 截图证据：`CUDACachingAllocator.cpp:838` + `NvMapMemAllocInternalTagged error 12`

## 四、今天新学到的知识点

| # | 知识点 | 内容 |
|---|---|---|
| 1 | **CSI 排线方向** | 开发板端：金属线**朝下**（朝板子）；摄像头端：金属线**朝后** |
| 2 | **`i2cdetect` 不能判断摄像头接线** | 摄像头供电（1.8V/2.8V）由驱动在探测时打开。驱动探测失败 → 电源没开 → I2C 扫不到。**"扫不到"是结果，不是原因** |
| 3 | **AE 需要多帧收敛** | 只抓 1 帧会得到全黑/纯噪声图。要抓 30~60 帧取最后一帧 |
| 4 | **系统更新会改启动配置** | 更新可能重置 extlinux.conf 的 DEFAULT，静默破坏 overlay 配置 |
| 5 | **CPU 也能跑 ASR** | 234M 参数的 SenseVoice，CPU 上 3.4 秒，不吃显存 |
| 6 | **CH340 的设备名** | 厂商驱动下是 `/dev/ttyCH341USB0`，不是 `/dev/ttyUSB0` |
| 7 | **USB 声卡的 Mic 控件可能是播放/录音共用** | 用 amixer 只加 `cap`，**绝不加 `unmute`**（会把播放通道打开造成回环啸叫） |
| 8 | **重启会清 /tmp** | 可复用脚本要放 `/home/nvidia/project/` |
